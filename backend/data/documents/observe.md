# Observability in Distributed Systems

Observability is the ability to understand what is happening inside a software system by examining the data it produces. Unlike traditional monitoring, observability helps engineers investigate unknown failures rather than only detecting known issues.

The three pillars of observability are logs, metrics, and traces.

## Logs

Logs are timestamped records generated by applications and infrastructure. They capture events, errors, warnings, and debugging information. Engineers use logs to reconstruct what happened during a request or background task.

Structured logging using JSON makes logs easier to search and analyze.

## Metrics

Metrics are numerical measurements collected over time. Common examples include CPU utilization, memory usage, request latency, request throughput, and error rate.

Prometheus is one of the most widely used systems for collecting and storing metrics.

## Traces

Distributed tracing follows a request as it travels through multiple services. Every operation is represented as a span, and together these spans form a trace.

Tracing helps engineers identify latency bottlenecks and understand service dependencies.

Tempo is an open-source distributed tracing backend commonly used with Grafana.

## Grafana

Grafana provides dashboards for visualizing metrics, logs, and traces. It integrates with Prometheus, Loki, and Tempo to provide a unified observability platform.

An effective observability stack allows engineers to troubleshoot production incidents much faster.
